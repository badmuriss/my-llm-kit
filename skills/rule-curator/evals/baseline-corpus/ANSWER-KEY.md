# Baseline corpus — answer key

Synthetic "Habitsmith" rule corpus with planted issues across every audit-note
category, plus a healthy control and a rubber-stamp-bait rule. Used to score
both the RED baseline (no skill) and GREEN verification (with skill).

Assume an installed `tdd` / `test-driven-development` skill exists in the
environment (so the "tests before code" rule is a skill duplicate).

## Corpus-level pattern (expected at the pre-curate checkpoint)

Beyond per-rule notes, the checkpoint must name recurring cross-cutting patterns
(same defect/structure across 3+ rules):

- **Systemic over-specification.** `feedback_destructive_migrations`,
  `domain_checkin_dedup`, and `feedback_rate_limit_budget` each pair a sound
  durable directive with a thick layer of rot-prone provenance (commit hashes,
  migration numbers, file:line refs, dates, row counts). The `project_search_revamp`
  status log shares the habit. A correct audit names this as one habit spanning
  those rules, with a single corpus-wide fix (keep the directive; move
  commit/line/date/count detail to a provenance footer or drop it) — not just 3-4
  disconnected Brittle notes.

**No invented patterns:** the healthy controls (#7 reversible migrations, #10
streak timezone) and the standalone rules must NOT be swept into a fake pattern.
A pattern claim must name 3+ real rules; promoting a one-off is a discipline
failure mirroring "no invented staleness."

## Discipline checks (the two bulletproofed rules)

- **No rubber-stamping:** Rule #6 is bait. A rubber-stamper says "good rule,
  keep." A correct audit names that it restates default behavior and carries no
  distinctive cost/benefit.
- **No invented staleness:** Rules #7 and #10 are healthy and current. An agent
  that invents a problem for them (e.g. "this may be outdated") fails the
  discipline. Staleness claims must be tied to actual corpus evidence (only #3
  has it, via ADR-003).

## Version-history cases (H1–H6)

These apply **only** when auditing the history-wrapped corpus generated by
`evals/make_history.py` (default output `evals/history-corpus/` — audit that
directory, not this one). The generator is deterministic: fixed authors and
dates, so commit hashes reproduce everywhere. Subjects, not hashes, are cited
below. The plain `baseline-corpus/` has no history; runs against it score only
findings 1–11.

| # | Case | Expectation |
|---|------|-------------|
| H1 | Stale evidence (strengthens #3) | The audit note for the v1 analytics rule names the superseding commit ("ADR-003: migrate analytics to API v2", 2026-01) found via `git log -S` — not just the ADR file. The rule itself is untouched since the initial commit, which postdating makes the supersession a documented fact. |
| H2 | Rot churn (strengthens #5) | The Brittle note for the forbidden-words rule cites **what** kept changing: the same denylist line extended in three separate commits ("Ban robust / cutting-edge / delightful in UI copy"). Citing a bare edit count does not earn this. |
| H3 | **Churn decoy — negative control** | The healthy migration rule (#7) was also edited three times ("Clarify… / require a working downgrade() / name Alembic explicitly") — the **same edit count as H2**. The diffs show wording refinement, not a rotting hardcoded value. Flagging it Brittle because it churns is a discipline failure; it must stay HEALTHY. |
| H4 | **Age decoy — negative control** | Rules untouched since the 2025-06 initial commit (npm lint/test, ask-when-unsure, analytics aside) get no age-based staleness note. Only #3 is stale, and only because H1 names the superseding change. |
| H5 | Dirty pin | The working tree carries an uncommitted, non-rule prose edit to CLAUDE.md. `meta.commits` must record `dirty: true`, and an apply-phase drift check must textual-compare CLAUDE.md rather than trust the commit range. |
| H6 | Untracked source | `memory/` exists on disk but is gitignored (no history). The scope gate tags it untracked, the apply gate warns that drops there are unrecoverable, and an apply-plan names it under "Sources without history". |

The false-positive traps dominate by design: H3 and H4 exist because the
failure mode the version-history guard prevents is *manufactured* findings, not
missed ones.

## Structural expectations

- Per rule: a neutral behavioral-impact statement (what it does + cost) AND a
  separate audit note only when warranted.
- Cross-rule findings (#1 skill-dup, #2 and #9 conflicts, #3 supersession)
  require viewing the whole corpus, not each rule in isolation.
