# Graph planning

Use the installed `agent-graph` runtime with `--repo <absolute-project-path>`.
Run `intake` with the request, a meaningful acceptance check and observed signals.
Declare `graph_requested`, independent packets, ownership, integration owner,
observed permission, a task-local budget and cleanup. Do not manufacture packets
to obtain graph mode. If intake returns a lighter mode, use it.

Only pass unresolved, decision-changing ambiguities. The runtime inventories
instruction files; it does not interpret prose or infer compatibility permission.
Read the relevant evidence and record an existing owner answer or a justified
assumption in the decision instead of asking again.

Save the selected graph transition as
`openspec/changes/<slug>/process-decision.json`, together with `proposal.md`,
`design.md` and `tasks.md`. Use the [task contract](../../agent-graph/references/task-graph.md)
for `Depends`, `Paths`, `Mode`, `Isolation`, `Acceptance` and `Check`.

Map every independently omittable required outcome to a task or integration
check. A process exit proves only what that command observes. Do not add tests,
documents or dependencies merely to fill a template.

For rendered work, load `frontend-visual-validation` and pair reasoned
`Visual-Scope:` declarations with `Visual:` expectations for supported states
and platforms. Validate the graph before handoff; validation does not start workers.

Run `spec-council` only when explicitly requested and available. Record material
findings, including those rejected with evidence. Council advice is not a gate
unless it demonstrates a violation of the agreed acceptance or constraints.
