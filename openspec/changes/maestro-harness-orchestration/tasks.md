# Tasks

## Cohesive implementation sessions

Task IDs, dependencies, Checks, evidence, and grades remain independent. They do not imply one terminal or one full briefing per task. A fresh run keeps one writer and reuses its exact owned session for each ordered group while profile, workspace, permission mode, and incarnation remain compatible:

- contracts and delegation: MLK-00, MLK-01, MLK-01R, MLK-02, MLK-03, MLK-04, MLK-04R, MLK-04C;
- placement and lifecycle: MLK-05, MLK-05R, MLK-06, MLK-06R, MLK-06D;
- quarantine and result integrity: MLK-06Q, MLK-06QR, MLK-06QO, MLK-15, MLK-16;
- projection, browser, learning, and skill integration: MLK-07, MLK-07B, MLK-07P, MLK-08L, MLK-08;
- portable Host lifecycle and evidence: MLK-09R, MLK-09, MLK-09L, MLK-10, MLK-10R, MLK-11, MLK-12, MLK-14;
- adaptive execution policy: MLK-17, MLK-17R, MLK-18, MLK-19, MLK-20;
- compatibility export: MLK-13.

Only independently useful read-only work or write packets with disjoint decisions, Paths, and integration Checks may overlap. The next task in a reused session receives incremental context, not the complete state or spec. Independent review runs once after the cohesive package or after a materially risky change. Broad gates run after the group, while each task still records its smallest sufficient Check.
